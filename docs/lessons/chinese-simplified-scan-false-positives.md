# 教訓：中文簡繁掃描的假陽性，與 subagent 自我驗證不可信

> **日期**：2026-09-30
> **關聯**：MyO 內容庫遷移（27 列繁中內容生成與修正）
> **狀態**：已解決

---

### 問題

**坑 1：subagent 回報「所有驗證通過」，實測有 4 類真錯誤**

寫內容的 subagent 自我報告六項驗證全數 PASS，但獨立複驗抓到：

| 缺陷 | 數量 |
|---|---|
| `cta_url` 欄位整欄缺失 | 27/27 列 |
| 簡體字（`無论`、`每一张`、`确保品质`、`环节`） | 42 處 |
| `image_prompt` 內簡體字（`five保养`、`seasonal回顾`） | 2 處 |
| 攝影用語（`最新作品` — 此品牌賣證書套，非攝影） | 2 處 |

它的修正腳本**只處理 5 個文案欄位，漏了 `image_prompt`**，且宣稱「簡體字乾淨」。

**坑 2：字表混入繁簡同形字，造成大量假陽性**

自製簡體字集合時，若以「簡體詞」字串串接（`"买卖东西开关无处备..."`），會把詞內的同形字一併收進集合：

| 收進去的字 | 實際情況 |
|---|---|
| 西（來自「东**西**」） | 繁簡同形，「西式」「中西」完全正確 |
| 划（來自「**划**算」） | 繁簡同形 |
| 制（來自「**制**度」） | 同形用字正確 |
| 配、估、俾、助 | 同形或港式正字 |

結果：驗證報 FAIL，但實際內容完全正確 —— 差點為了讓檢查通過而去「修正」正確的繁體字。

**更嚴重的是反向污染**：字表若只收「明確簡體」，會漏掉嵌在詞組內的情況（`保养` 的「养」不在單字清單裡）。

### 教訓

**subagent 的自我驗證報告不可信，交付物必須獨立複驗。** 它的檢查與它的產出同一個上下文，容易把「我寫了什麼」當成「驗過了什麼」。

**中文字形驗證不能靠手寫字表。** 繁簡同形字、港式正字（俾）、繁體變體（週）會同時造成假陽性與假陰性。可靠做法是**逐字比對 + 人工看上下文**。

### 解法

**1. 驗證前先確定每個字是否真為簡體 —— 看上下文，不看字表：**

```python
for i, ch in enumerate(t):
    if ch in SIMP:
        print(f"…{t[max(0,i-6):i+7]}…")   # 人工判斷這個用法是否真的簡體
```

確認為真簡體後再修：確 → 確、录 → 錄。無法確定同形字（西/划/制）則維持原樣。

**2. 修正腳本要涵蓋「全部」目標欄位，並在覆蓋清單內斷言：**

```python
FIELDS = ['Idea','ig_hook','ig_caption','threads_hook','threads_body','image_prompt']
for r in rows:
    for f in FIELDS:          # 漏一個欄位 = 遺漏一整批錯誤
        ...
```

**3. 同形字與簡體字分開維護：**

```python
SIMP = {...}              # 只收繁體明確不同寫法者
SAME_IN_BOTH = set('西划制助估俾见周干只冲面里台后系杆斗')
SIMP -= SAME_IN_BOTH       # 詞組串接誤收的同形字
```

**4. 遇到同形字衝突，優先改文案而非放寬檢查：**

`茶几` 的「几」與簡體「几」同形。與其把「几」加進白名單（削弱檢查），不如把「茶几上」改成「矮桌上」—— 保留嚴格檢查比遷就一個字形划算。

### 預防

1. **subagent 交付的資料檔（JSON/CSV/YAML）一律獨立複驗**，不採信其自我報告
2. **寫修正腳本前列出完整欄位清單**，逐欄處理，並在腳本內 assert 覆蓋到所有欄位
3. **中文字形驗證：先看上下文再判定**，不要相信手寫字表；同形字（西/划/制/面/里/后/干）一律視為合法
4. **修正後必須回讀驗證**（從 Notion / DB 讀回實際值比對），不能只驗本地 JSON
5. **驗證腳本本身要測試過** —— 本次 `final_verify.py` 初版就有兩個 bug：`Idea` 是 `title` 屬性卻用 `rich_text` 讀取（誤判為空）、SIMP 表混入繁體字形。驗證腳本報 FAIL 時，先確認腳本本身是否可信
